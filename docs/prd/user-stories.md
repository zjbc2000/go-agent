# 用户故事与验收标准

## 1. 账号与权限

### US-AUTH-01 登录助手

作为用户，我希望用账号密码登录，以便访问自己的会话和文档。

验收标准：

- 正确凭据可以登录并进入聊天页。
- 错误凭据不会泄露账号是否存在以外的敏感信息。
- 登录态过期后，前端提示重新登录，业务数据不丢失。

### US-AUTH-02 管理账号

作为管理员，我希望新增、禁用和重置普通用户账号，以便控制系统访问。

验收标准：

- 只有管理员可以执行账号管理。
- 禁用账号无法新建会话或调用模型。
- 管理操作写入审计日志。

## 2. 聊天与会话

### US-CHAT-01 流式聊天

作为用户，我希望看到助手逐步输出，以便知道请求仍在处理。

验收标准：

- 消息通过 SSE 增量渲染。
- 前端显示连接、生成、完成和失败状态。
- 断线后可重连，服务端不会重复保存同一条消息。

### US-CHAT-02 查找历史会话

作为用户，我希望根据 session ID 和历史列表恢复会话，以便继续之前的讨论。

验收标准：

- 每个会话有唯一 session ID。
- 只能加载自己的消息正文。
- 管理员列表只显示会话元数据，不显示消息正文。

### US-CHAT-03 控制上下文注入

作为管理员，我希望开关记忆、Skill、MCP 等能力，以便控制助手上下文和工具范围。

验收标准：

- 关闭能力后，Agent 不读取或注入对应上下文。
- 用户端不出现管理员配置项。
- 每次配置变更可审计。

## 3. 记忆与文档

### US-DOC-01 管理记忆

作为用户，我希望查看、编辑、删除自己的记忆，以便纠正助手对我的理解。

验收标准：

- 支持偏好、兴趣、目标、状态摘要和对话摘要等类型。
- 删除采用可审计的软删除策略。
- 助手生成的记忆只能先进入待确认状态。

### US-DOC-02 管理兴趣和任务

作为用户，我希望管理兴趣和任务文档，以便持续跟踪自己想尝试的方向。

验收标准：

- 支持创建、查看、编辑、删除。
- 任务至少能表达标题、步骤、状态、约束和反馈。
- 下次聊天能读取已确认内容。

### US-DOC-03 恢复历史版本

作为用户，我希望查看并恢复文档历史版本，以便撤销不满意的调整。

验收标准：

- 每次确认后的修改生成递增版本。
- 版本包含修改时间、修改人和内容快照。
- 恢复版本会生成新的当前版本，不覆盖历史记录。

## 4. 兴趣规划与 HITL

### US-PLAN-01 识别兴趣意图

作为用户，我希望用自然语言描述近况或兴趣，助手能理解我的意图并在必要时追问。

验收标准：

- 能区分倾诉、兴趣探索和任务反馈等基本意图。
- 信息不足时先追问，不直接生成武断计划。
- 可引用已确认记忆，但不引用待确认草稿。

### US-PLAN-02 生成可执行草稿

作为用户，我希望兴趣被拆解成清晰步骤，以便判断是否真的可执行。

验收标准：

- 草稿包含兴趣目标、步骤、前置条件和可调整字段。
- 草稿持久化为待确认状态。
- 生成过程可以在 LangGraph 节点暂停等待用户。

### US-PLAN-03 确认或修改草稿

作为用户，我希望确认、编辑、驳回或重新生成草稿，以便计划符合我的实际情况。

验收标准：

- 四种操作均可从聊天页完成。
- 修改后确认保存用户最终内容和原始助手草稿。
- 未确认内容不会进入正式上下文。

### US-PLAN-04 后续反馈调整

作为用户，我希望下次聊天时告诉助手进展或困难，助手能提出调整方案。

验收标准：

- 助手读取相关兴趣、任务和反馈。
- 调整内容先生成新草稿。
- 用户确认后才更新正式文档和版本。

## 5. Skill 与沙箱

### US-EXEC-01 确认 Skill 草稿

作为用户，我希望看到 Skill 的用途、权限和影响后再启用它。

验收标准：

- Skill 显示输入、步骤、可读写数据、网络需求和限制。
- 用户确认后才进入生效状态。
- Skill 支持停用、编辑、删除和版本恢复。

### US-EXEC-02 确认数据变更

作为用户，我希望在 Skill 修改或删除数据前明确确认，以便避免误操作。

验收标准：

- 执行摘要包含目标、数据类型、变更数量和外部请求。
- 用户拒绝时不产生数据变更。
- 重复确认请求具备幂等性。

### US-EXEC-03 受限联网沙箱

作为管理员，我希望 Skill 在受限沙箱中联网运行，以便获得必要工具能力而不暴露系统。

验收标准：

- 阻断回环、私有网段和云服务元数据地址。
- 限制 CPU、内存、磁盘、运行时间和并发。
- 记录网络目标、工具调用、数据变更和错误。

## 6. 模型、监控与后台

### US-ADMIN-01 配置模型供应商

作为管理员，我希望切换 OpenAI-compatible 模型供应商和模型，以便控制成本和能力。

验收标准：

- 支持配置 API Base、模型名、上下文长度和默认参数。
- 密钥脱敏展示并不进入普通日志。
- 禁用的模型不能被 Agent 选择。

### US-ADMIN-02 配置 token/费用限额

作为管理员，我希望按 token 或费用设置限额，以便控制资源消耗。

验收标准：

- 支持全局、用户和供应商维度的限额配置。
- 达到限额时调用被拒绝并返回原因。
- 使用量按请求记录并可聚合查看。

### US-ADMIN-03 查看运行指标

作为管理员，我希望查看调用量、延迟、错误和费用，而不接触用户聊天正文。

验收标准：

- 可以按时间、模型、用户和状态筛选指标。
- 原始消息内容不出现在管理界面和监控日志。
- Langfuse/OpenTelemetry 数据经过脱敏。

### US-ADMIN-04 管理 Skill/MCP

作为管理员，我希望启用、停用和配置 Skill/MCP，以便控制助手可用的工具。

验收标准：

- 配置变更立即影响后续请求。
- 禁用项不会被上下文注入或调用。
- 所有变更都有操作者和时间记录。
