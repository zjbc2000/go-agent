# 聊天页设计说明

**版本**：v2.0  
**关联需求**：[PRD](../../prd/prd.md) 的 `CHAT`、`DOC`、`HITL` 和 `EXEC` 需求  
**范围**：普通用户聊天页，不包含管理员后台  
**交付图**：[Logo 黑白线稿](./assets/goudan-logo-outline.svg)｜[方案 A：浅色桌面稿](./assets/goudan-chat-desktop-light.svg)｜[方案 B：深色桌面稿](./assets/goudan-chat-desktop-dark.svg)

将 SVG 直接拖入 Figma 即可查看和标注。它们是精确的视觉参考稿，不替代后续用 Figma Auto Layout/组件变量搭建的可维护源文件；本文档中的 Token、尺寸和状态才是实现依据。

## 0. 已确认的 v2 决策

- 产品名称：**苟蛋**。
- Logo：基于参考图的坐姿外形，采用原创黑白轮廓线稿；浅色主题使用黑色描边，深色主题使用白色描边。
- 主题：浅色和深色模式均为 MVP 范围，使用同一组语义 Token 和组件状态，不维护两套交互逻辑。
- 一级导航名称：原“文档”统一改为 **规划**；页面内部仍以记忆、兴趣、任务和 Skill 作为数据分类。
- 兴趣/任务草稿：在**消息卡片内直接编辑**，而不是打开右侧/底部详情抽屉。
- 优先级：先完整实现 1440px 桌面体验；移动端 v1 仅保留为后续适配参考。

## 1. 设计目标

聊天页是产品的主工作区。设计优先级是：

1. 让用户先愿意表达，再让助手提出计划；不能把聊天页做成待办事项管理器。
2. 将“待确认”和“已经生效”明确区分，任何自动写入前都让用户看清影响。
3. 让会话、记忆、兴趣和任务在需要时可见，但不持续挤占聊天空间。
4. 让流式生成、断线、错误和恢复有可理解的反馈，避免用户猜测系统状态。

v2 视觉改为更冷静、极简的高对比工作区：中性黑白为主体，浅色模式用电蓝表达唯一主操作，深色模式用荧光黄绿表达唯一主操作。圆角控制在 6px，取消大面积阴影、渐变和疗愈类装饰；苟蛋的黑白线稿只作为品牌锚点，不参与功能状态表达。

## 2. 页面布局

### 2.1 桌面端，>= 1024px

```text
+------------------+----------------------------------------+-----------------------+
| 会话导航 280px   | 对话主区 min 560px / max 760px         | 上下文栏 312px        |
|                  |                                        |                       |
| 标识、新建会话   | 会话标题、保存状态、更多操作           | 本次对话 / 已确认上下文 |
| 搜索、会话分组   | 消息时间线、草稿/HITL 卡片             | 兴趣、任务、记忆摘要   |
| 用户菜单         | 固定输入区、发送/停止生成              | 待确认数量入口         |
+------------------+----------------------------------------+-----------------------+
```

- 左栏负责定位会话和创建会话，不承载文档管理。
- 中间是唯一的主要阅读与输入区域；消息列最大宽度为 720px，避免长文本难读。
- 右栏只显示和当前会话有关的已确认上下文与待确认项。点击“规划”进入统一规划页，避免将完整文档编辑塞入聊天侧栏。
- 三栏之间以 1px 边框分隔，只有 HITL 草稿采用实体卡片，避免“卡片套卡片”。

### 2.2 移动端，390px

```text
+--------------------------------------+
| 菜单  会话标题 / 已保存          更多 |
+--------------------------------------+
|              消息时间线              |
|       流式状态、待确认草稿卡片        |
|                                      |
+--------------------------------------+
| 多行输入框                 发送/停止 |
+--------------------------------------+
| 聊天             规划             我 |
+--------------------------------------+
```

- 会话列表由左上角菜单打开的抽屉承载。
- “本次对话”上下文由标题旁的上下文按钮打开底部抽屉；不同时显示桌面右栏。
- 任务草稿在窄屏下折叠为“目标 + 前 2 步 + 展开全部”，确认、编辑、重新生成保留为可点击文本按钮，最小触达区 44px。
- 底部导航只放聊天、规划、我的三个顶级目的地；管理功能不出现在普通用户导航中。

| 会话头部 | 显示标题、保存/重连状态、会话级更多操作 | 长篇会话说明 |
| 消息时间线 | 呈现用户与助手消息、引用、流式输出、HITL 和错误恢复 | 全局导航 |
| 草稿卡片 | 展示待确认的兴趣/任务变更，提供确认、编辑、驳回/重生成 | 执行未确认的写入 |
| 上下文栏/抽屉 | 显示已确认的兴趣、任务、记忆和待确认数量 | 完整文档批量管理 |

## 5. 关键交互

### 5.1 流式输出

1. 用户发送后，用户消息立即进入时间线，输入区进入“发送中”状态。
2. 助手消息先显示头像、细小的“正在思考”文本和三个低对比跳点；首个 token 到达后替换为正文。
3. 流式期间，“发送”替换为 `Square` 停止按钮；停止只中断后续生成，已收到文本保留并标记“已停止”。
4. 新消息到达时仅在用户位于底部时自动跟随；用户上滑阅读历史时显示“回到最新消息”按钮，不强制滚动。

### 5.2 兴趣/任务草稿与 HITL

1. 助手先以自然语言解释为什么提出计划，再插入“待你确认”草稿卡片。
2. 草稿卡片固定展示目标、步骤数、预计投入和前两步；用户展开后查看完整步骤与约束。
3. **确认计划**为唯一主操作，写入正式文档并将卡片变为“已保存”摘要。
4. **编辑**在同一张消息卡片内展开为表单。保存后折叠为用户修改后的版本摘要；取消则还原未编辑的草稿，不离开聊天位置。
5. **重新生成**保留当前草稿版本，调用 LangGraph 生成替代草稿；新旧草稿可切换比较。
6. **驳回**进入溢出菜单，要求选择“暂不需要”或“方向不合适”，反馈给下一轮对话；不执行写入。
7. 用户离开后，待确认内容保存在会话和右栏的“待确认 1”入口，重新进入可恢复。

### 5.3 断线与错误

- SSE 断开时，在会话头部下方显示非阻塞横幅：“连接已中断，正在恢复…”。横幅有重试与关闭按钮。
- 重连成功后显示短暂“已恢复”，消息按 `message_id` 去重；不重复显示或保存用户消息。
- 模型错误、超限和输入失败都在出错消息附近显示具体原因和“重试”操作，不能只依赖红色。
- 流式请求超过 300ms 但尚无 token 时显示活动状态；不以长时间全页 Loading 覆盖对话历史。

### 5.4 空会话

- 新会话不显示空白画布，而是展示简短引导：“从最近的状态或想尝试的事开始。”
- 提供三个可直接填入输入框的示例：倾诉近况、探索兴趣、反馈进展。示例是快捷输入，不会自动发送。

## 6. 设计 Token

| 类别 | Token | 值 | 使用方式 |
| --- | --- | --- | --- |
| 背景 | `--surface-canvas` | 浅：`#F7F7F8` / 深：`#0C0D0E` | 页面背景、非重点区域 |
| 背景 | `--surface-default` | 浅：`#FFFFFF` / 深：`#141518` | 侧栏、输入区、草稿卡片 |
| 背景 | `--surface-muted` | 浅：`#F0F2F5` / 深：`#1E2025` | 用户消息、选中会话、轻提示 |
| 主色 | `--primary` | 浅：`#246BFD` / 深：`#D9FF5A` | 唯一主操作、焦点、已确认状态 |
| 主色 | `--primary-hover` | 浅：`#1957D7` / 深：`#C5ED43` | 悬停和按下 |
| 文本 | `--text-primary` | 浅：`#111214` / 深：`#F5F7F8` | 标题和正文 |
| 文本 | `--text-secondary` | 浅：`#5E6470` / 深：`#A7ABB4` | 辅助文本 |
| 边框 | `--border-subtle` | 浅：`#E2E4E8` / 深：`#2A2D33` | 分隔线和控件边框 |
| 待确认 | `--warning-bg` / `--warning-text` | 浅：`#FFF6E8` / `#9A4A00`；深：`#332710` / `#FFD27D` | 草稿标签和提醒 |
| 错误 | `--danger-bg` / `--danger` | 浅：`#FFF0F0` / `#C43131`；深：`#32191B` / `#FF8A8A` | 失败提示和破坏性操作 |
| 字体 | `--font-sans` | Inter, PingFang SC, Microsoft YaHei, sans-serif | 全站文本 |
| 字号 | `--text-body` | 16px / 1.6 | 消息正文与输入 |
| 字号 | `--text-meta` | 13px / 1.4 | 时间、状态和标签 |
| 圆角 | `--radius-sm` / `--radius-md` | 6px / 8px | 控件 / 草稿卡片 |
| 间距 | `--space-*` | 4, 8, 12, 16, 24, 32px | 统一间距体系 |

不使用大面积渐变、拟物阴影、装饰性插画或高饱和多色状态。主色只表达可操作的主要路径，不承担所有层级区分；深色模式不使用纯黑文字层叠，而是以 3 个中性表面层级建立结构。

## 7. 响应式规则

| 断点 | 导航 | 对话区 | 上下文 | 输入区 |
| --- | --- | --- | --- | --- |
| `>= 1280px` | 280px 全侧栏 | 居中，最大 760px | 312px 右栏常驻 | 固定于对话区底部 |
| `1024-1279px` | 72px 图标窄栏，悬浮展开 | 占据剩余空间 | 以侧边 Sheet 打开 | 固定于主区底部 |
| `768-1023px` | 72px 窄栏 | 最大 680px | Sheet 打开 | 固定于主区底部 |
| `< 768px` | 会话抽屉 + 底部三项导航 | 单列，16px 页边距 | 底部 Sheet | 固定在安全区上方 |

所有文本优先换行而不是截断；会话标题可以单行省略，并在悬停/长按时显示完整标题。移动端不允许水平滚动。

## 8. 无障碍要求

- 正文与背景、主按钮与背景的对比度至少 4.5:1；不可只用颜色表达“待确认”“断线”“失败”。
- Tab 顺序：跳到主内容 → 会话导航 → 会话头部 → 消息操作 → 草稿操作 → 输入区 → 上下文栏。
- 图标按钮都使用 `Tooltip` 和可访问名称，例如“打开会话列表”“停止生成”“显示本次对话上下文”。
- 每个交互目标最低为 44 x 44px；移动端相邻操作间距至少 8px。
- 流式文本用 `aria-live="polite"`，错误用 `role="alert"`；避免每个 token 触发一次屏幕阅读器播报。
- HITL 内联编辑展开后，焦点进入第一个可编辑字段；Esc 取消未保存编辑并返回“编辑”按钮。
- 所有 150-300ms 的动效在 `prefers-reduced-motion` 下关闭或简化；不使用闪烁表示网络状态。
- 以 390px、768px、1024px、1440px 和 200% 浏览器缩放验收布局。

## 9. 状态规范

| 状态 | 视觉反馈 | 可执行操作 |
| --- | --- | --- |
| 空会话 | 标题、简短引导、三个快捷输入 | 点击示例填入输入框、直接输入 |
| 流式生成 | 助手头像、活动文本/跳点、停止按钮 | 停止生成、继续阅读历史 |
| 待确认草稿 | 琥珀色“待你确认”标签、草稿卡片 | 确认、编辑、重新生成、驳回 |
| 已保存草稿 | 深青色勾选和版本摘要 | 查看文档、查看版本 |
| 断线重连 | 非阻塞横幅和头部状态 | 立即重试、关闭横幅 |
| 请求失败 | 靠近失败消息的错误说明 | 重试、复制错误 ID |
| 模型超限 | 明确“本日额度已用尽” | 返回、切换至管理员允许的备用模型（若开放） |
| 无上下文 | 右栏空状态，说明尚未确认任何兴趣/任务 | 在聊天中开始探索 |
