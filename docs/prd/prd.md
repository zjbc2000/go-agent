# 兴趣陪伴与规划助手 PRD

**版本**：需求基线 v1.0  
**状态**：已确认，可进入设计与开发  
**日期**：2026-08-03

## 1. 产品概述

这是一个以聊天为入口的个人 AI 助手。它优先倾听和理解用户的情绪、近况和口语化表达，再把用户表达的兴趣逐步转化为经过用户认可的可执行步骤。助手不会替用户完成现实任务，而是维护兴趣、任务、记忆和可复用 Skill 文档，并在后续聊天中根据用户反馈持续调整。

首版以个人使用为优先，但保留管理员账号、账号创建和运营管理能力。管理员可以使用助手；管理员只能查看系统元数据、错误、调用量和费用等信息，不能查看普通用户的聊天正文或记忆内容。

## 2. 产品目标

### 2.1 MVP 目标

1. 用户可以通过自然语言与助手进行流式对话。
2. 助手可以理解情绪表达和兴趣意图，并在必要时继续追问。
3. 助手可以将兴趣拆解为用户可理解、可修改的任务草稿。
4. 用户通过 Human-in-the-Loop 确认、修改、驳回或重新生成草稿。
5. 记忆、兴趣、任务和 Skill 以结构化文档保存，用户可以管理并查看历史版本。
6. 下一次聊天可以读取相关文档，并根据用户反馈自动调整内容。
7. 已确认的 Skill 可以在受限沙箱中执行助手自身数据的 CRUD 操作；高风险操作必须经过用户确认。
8. 管理员可以管理账号、模型供应商、模型参数、调用限额、Skill、MCP 和运行监控。

### 2.2 非目标

- MVP 不做自动提醒、邮件、日历或其他外部通知。
- MVP 不做自动替用户执行现实世界任务。
- MVP 不做多智能体团队栏；主助手使用 LangGraph，AutoGen 仅保留后续扩展位。
- MVP 不做 Elasticsearch；优先使用 PostgreSQL、全文检索和 pgvector（如需要语义检索）。
- MVP 不做公开注册、复杂组织/租户、计费和商业化后台。
- MVP 不把助手定位为心理治疗或诊断工具；不在首版实现危机干预流程。
- MVP 不允许未经确认的 Skill 或沙箱操作修改数据。

## 3. 用户与权限

### 3.1 角色

| 角色 | 说明 |
| --- | --- |
| 普通用户 | 使用聊天、会话历史、记忆/兴趣/任务/Skill 文档和确认流程。 |
| 管理员 | 可使用全部普通用户能力；额外管理账号、模型、限额、Skill、MCP、错误、调用量和系统元数据。 |

首版以单人使用为优先，但数据模型必须带 `user_id`，避免后续扩展账号时重构核心表。

### 3.2 权限边界

- 登录采用账号密码；实现上优先使用 Supabase Auth，不在业务表中保存明文密码。
- 管理员可以新增、禁用和重置普通用户账号。
- 用户只能访问自己的会话、消息、记忆、兴趣、任务、Skill 和版本记录。
- 管理员不能查看用户聊天正文、消息内容和记忆正文；可查看会话 ID、时间、状态、耗时、token、费用、错误和模型信息。
- 管理配置按管理员角色保护，并写入审计日志。

## 4. 核心用户流程

### 4.1 情绪倾诉流程

1. 用户登录并进入聊天页。
2. 用户描述近况、情绪或困惑。
3. 助手通过流式消息倾听、复述和追问，不急于生成任务。
4. 助手根据既有记忆和本次对话判断是否需要更新记忆草稿。
5. 需要更新时，将记忆以可编辑文档呈现；用户确认后写入正式记忆。

### 4.2 兴趣规划流程

1. 用户用口语化语言描述感兴趣的事物或想尝试的方向。
2. LangGraph 助手识别兴趣、目标、约束和当前状态；信息不足时继续提问。
3. 助手生成兴趣/任务草稿，并保存为 `pending_confirmation`。
4. 前端以可编辑文档或卡片展示草稿，用户可以确认、修改后确认、驳回或重新生成。
5. 用户确认后，兴趣和任务写入正式文档，任务进入 `active`。
6. 用户在后续聊天中反馈进展、困难或新偏好。
7. 助手读取相关文档，提出调整并生成新的草稿；仍需用户确认后生效。

### 4.3 Skill 流程

1. 助手识别出可复用的操作模式，生成 Skill 草稿。
2. Skill 草稿保存为 `draft`，展示名称、用途、输入、步骤、数据权限和网络需求。
3. 用户确认后，Skill 变为 `active`；用户可以编辑、停用、删除并查看历史版本。
4. 每次运行前展示执行摘要和预计影响；会修改数据或产生外部写操作时必须再次确认。
5. Skill 在隔离沙箱中执行，记录输入、输出、工具调用、变更和错误。

## 5. 功能需求

### 5.1 认证与账号（AUTH）

- `AUTH-01` 用户可以使用账号密码登录、退出和保持登录状态。
- `AUTH-02` 管理员可以新增普通用户、禁用账号和重置密码。
- `AUTH-03` 登录后按角色返回可用页面和操作权限。
- `AUTH-04` 所有业务 API 校验用户身份，并按 `user_id` 做数据隔离。
- `AUTH-05` 密码、会话令牌和密钥不得写入日志。

### 5.2 会话与流式聊天（CHAT）

- `CHAT-01` 用户可以新建会话；每个会话具有唯一 `session_id`。
- `CHAT-02` 用户可以按 `session_id` 加载历史消息和会话元数据。
- `CHAT-03` 助手响应通过 SSE 流式返回，前端显示连接中、生成中、完成、失败和重连状态。
- `CHAT-04` 消息保存角色、内容、时间、模型、token、费用、状态和错误摘要。
- `CHAT-05` 主助手使用 LangGraph；节点至少覆盖意图识别、上下文组装、回复生成、文档草稿生成和用户确认恢复。
- `CHAT-06` 记忆、Skill、MCP 等上下文注入能力由管理员配置开关；关闭后不得注入对应上下文或工具。
- `CHAT-07` 用户界面不暴露仅管理员可用的系统开关。

### 5.3 记忆、兴趣和任务文档（DOC）

- `DOC-01` 用户可以查看、创建、编辑和删除自己的记忆、兴趣、任务文档。
- `DOC-02` 文档支持结构化字段和可读正文；助手通过受控工具执行 CRUD。
- `DOC-03` 文档删除必须可审计；默认软删除，避免误删后无法追溯。
- `DOC-04` 每次确认后的修改生成历史版本，至少保存版本号、修改人、修改时间和变更内容。
- `DOC-05` 用户可以查看历史版本；MVP 支持恢复指定历史版本。
- `DOC-06` 文档状态至少包括草稿、待确认、生效、已停用、已删除。
- `DOC-07` 记忆至少支持偏好、兴趣、目标、状态摘要、任务反馈和对话摘要等类型。
- `DOC-08` 仅在用户确认后将助手生成的记忆或计划草稿写入正式文档。

### 5.4 Human-in-the-Loop（HITL）

- `HITL-01` 兴趣/任务草稿生成后暂停 LangGraph，等待用户输入。
- `HITL-02` 前端提供确认、修改后确认、驳回和重新生成操作。
- `HITL-03` 未确认的草稿只能保存在待确认状态，不得作为正式任务或记忆注入长期上下文。
- `HITL-04` 用户修改内容后，系统保存用户最终确认版本和原始助手草稿。
- `HITL-05` 用户离开页面后可以从会话或待确认列表恢复确认流程。

### 5.5 Skill、MCP 与沙箱（EXEC）

- `EXEC-01` 助手可以生成 Skill 草稿；必须由用户确认后生效。
- `EXEC-02` 管理员可以启用、停用、编辑和删除 Skill/MCP 配置。
- `EXEC-03` Skill 的权限声明包括可读写的数据类型、文件范围、网络需求和超时。
- `EXEC-04` Skill 只能通过受控工具访问记忆、兴趣、任务等助手数据。
- `EXEC-05` 涉及写入、删除或外部副作用的执行必须展示摘要并等待用户确认。
- `EXEC-06` 沙箱限制执行时间、CPU、内存、磁盘和并发数；禁止访问云服务元数据地址和内网地址。
- `EXEC-07` 沙箱允许联网，但必须经过网络策略检查；支持域名白名单配置，默认阻断私有地址、回环地址和未解析的内部地址。
- `EXEC-08` 沙箱每次运行记录调用者、Skill 版本、输入摘要、工具调用、网络目标、数据变更、输出、耗时和错误。
- `EXEC-09` 沙箱失败、超时或触发策略时，必须返回可读错误且不得产生未记录的部分变更。

### 5.6 管理后台与监控（ADMIN）

- `ADMIN-01` 管理员可以管理账号、角色、状态和密码重置。
- `ADMIN-02` 管理员可以配置模型供应商、模型、上下文长度、默认参数和启停状态。
- `ADMIN-03` 模型供应商优先兼容 OpenAI API 格式；API Key 使用密钥管理方式保存，页面只显示脱敏值。
- `ADMIN-04` 管理员可以按 token 或费用设置全局、用户或供应商限额；达到限额时阻止调用并返回原因。
- `ADMIN-05` 管理员可以查看会话元数据、调用量、token、费用、延迟、错误率和沙箱运行结果，但不可查看聊天正文。
- `ADMIN-06` 管理员可以查看和筛选错误日志、审计日志和系统事件。
- `ADMIN-07` 管理员可以管理记忆/Skill/MCP/模型注入开关；变更写入审计日志。
- `ADMIN-08` 集成 Langfuse 和 OpenTelemetry 时必须进行内容脱敏，不上传原始敏感消息作为可见日志。

## 6. 页面与交互范围

### 6.1 普通用户

- 登录页
- 聊天页：消息流、会话列表、待确认草稿、执行确认、错误和重连状态
- 会话历史页：按会话 ID、时间和标题查找
- 文档页：记忆、兴趣、任务、Skill 的列表、详情、编辑、删除和历史版本

### 6.2 管理员

- 账号管理
- 模型供应商与模型配置
- token/费用限额
- Skill/MCP 与上下文注入开关
- 会话与调用元数据
- 错误、审计、调用量和费用监控

## 8. 技术约束与建议架构

### 8.1 部署边界

- Next.js/React：页面、鉴权集成、轻量 BFF、SSE 转发，优先部署到 Vercel。
- Supabase：Auth、PostgreSQL、RLS、备份；必要时使用 pgvector 做语义检索。
- Python Agent 服务：LangGraph 主助手、上下文组装、受控数据工具和模型网关调用。
- Sandbox 服务：与 Agent 服务隔离运行，执行资源限制、网络策略和审计。
- LiteLLM Proxy：统一 OpenAI-compatible 模型供应商、token/费用统计和路由；也可以先用等价的 provider adapter，接口不得绑死单一供应商。
- Langfuse/OpenTelemetry：调用追踪、延迟、错误、token 和费用监控；原始内容按隐私策略脱敏。
- Celery/RabbitMQ：MVP 没有提醒和长期后台任务时不是硬依赖；为沙箱异步运行和后续扩展预留接口。

### 8.2 SSE 与长任务

Vercel 适合部署 Next.js 前端和轻量 API，但不承担长期 Agent worker、沙箱进程或队列消费者。SSE 可以由 Next.js 转发来自 Python Agent 服务的流；沙箱和长运行任务必须走独立服务，并向前端返回可恢复的运行 ID。

### 8.3 检索策略

MVP 使用 PostgreSQL 普通索引、全文检索和按需的 pgvector。只有在消息规模、聚合分析或复杂全文检索明显超过 PostgreSQL 能力时，才评估 Elasticsearch；引入前需要用真实查询和数据规模做基准测试。

## 9. 非功能需求

### 9.1 安全与隐私

- 所有业务表启用 RLS 或等价的服务端权限校验。
- 用户消息和记忆默认不进入管理员可见的原始日志。
- API Key、密码、令牌和沙箱凭据不得明文持久化或写日志。
- 所有管理变更、文档确认、Skill 执行和沙箱变更必须可审计。
- 沙箱采用最小权限、短时凭证、资源限制、网络隔离和可回滚的数据变更。

### 9.2 性能与可靠性目标

以下为 MVP 目标，模型供应商本身的延迟单独统计：

- 聊天请求成功建立 SSE 的 p95 不超过 3 秒。
- 流式连接断开后，用户可以重连并恢复会话状态，不重复写入消息。
- 普通 CRUD API p95 不超过 500ms（不含模型调用）。
- 关键写入使用幂等键，重复提交确认不生成重复版本或重复任务。
- Supabase 数据启用备份；文档版本和审计日志不可因普通删除丢失。

### 9.3 可维护性

- 前后端 API 契约、事件格式和错误码版本化。
- Agent 节点、工具权限和模型适配器可单元测试。
- 关键用户流程具备端到端测试：登录、聊天流、草稿确认、文档版本、Skill 确认和沙箱审计。
- 项目目录按 `web`、`agent-service`、`sandbox`、`infra`、`docs` 等边界组织，避免把 Agent 逻辑塞入页面组件。

## 10. MVP 验收标准

1. 用户和管理员可以账号密码登录；管理员可以新增账号。
2. 用户可以新建会话、按 `session_id` 查看历史记录并进行流式聊天。
3. 主助手通过 LangGraph 工作，管理员可以关闭记忆、Skill、MCP 等上下文能力，关闭后不再注入。
4. 助手能从自然语言识别兴趣/任务意图，在信息不足时追问。
5. 助手能生成兴趣和任务草稿并持久化；用户可以确认、编辑确认、驳回和重新生成。
6. 未确认草稿不会成为正式记忆、兴趣或任务；确认后生成可追溯版本。
7. 用户可以管理记忆、兴趣、任务和 Skill，并查看和恢复历史版本。
8. 后续会话能读取已确认文档，根据反馈生成新的调整草稿。
9. Skill 需用户确认后生效；写入/删除操作每次执行前需要确认。
10. 沙箱能执行助手数据 CRUD，允许联网但阻断内网/元数据地址并限制资源，所有运行可审计。
11. 管理员可以配置 OpenAI-compatible 模型供应商、模型、上下文长度及 token/费用限额。
12. 达到限额时模型调用被阻止并返回可理解的错误。
13. 管理员可以查看会话元数据、调用量、token、费用、延迟、错误和审计事件，但看不到用户聊天正文。
14. 关键功能有自动化测试，且部署在 Vercel + Supabase 的 MVP 环境可运行。

## 11. 风险与取舍

| 风险 | 应对 |
| --- | --- |
| 沙箱联网导致 SSRF、数据外泄或资源滥用 | 私有地址阻断、域名策略、资源上限、确认机制、审计和独立运行时。 |
| 情绪陪伴误导用户 | 产品文案和系统提示明确能力边界；不宣称诊断或治疗。危机响应不在 MVP 范围，需在公开发布前重新评审。 |
| 多模型 token/费用统计不一致 | 通过 LiteLLM 或统一适配器归一化 usage；保存原始供应商响应摘要用于校验。 |
| Vercel Serverless 不适合长任务 | Next.js 只做前端/BFF/SSE 转发，Agent 和沙箱独立部署。 |
| 文档自动写入破坏用户信任 | 所有助手写入先生成草稿，用户确认后生效，保留历史版本。 |
